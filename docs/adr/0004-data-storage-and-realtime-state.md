# ADR-0004: Room, PostgreSQL, Redis 역할 분리

- 상태: Accepted
- 결정일: 2026-08-25

## 맥락

Android 오프라인 실행, 서버 영구 데이터, 수백만 방문자 규모의 실시간 추천 상태는 서로 다른 저장 특성을 요구한다.

## 결정

### Room/SQLite

Android의 프로젝트 설정 캐시, 최근 추천 이력, 런타임 설정과 동기화 대기열을 저장한다.

### PostgreSQL

서버의 프로젝트, 콘텐츠, 장소, 규칙, 추천 이력, 관리자 계정과 감사 로그의 영구 원본이다.

### Redis

대규모 트래픽의 설정 캐시, 최근 추천 카운터, 직전 장소, idempotency, heartbeat, 원자적 추천 예약과 실시간 상황판 이벤트를 담당한다.

Redis는 영구 데이터 원본이 아니며 PostgreSQL 또는 이벤트 로그에서 재구성할 수 있어야 한다.

## 결과

- 하나의 DB 엔진으로 모든 역할을 억지로 통일하지 않는다.
- Redis 장애 시 PostgreSQL 기반 저하 운영 경로가 필요하다.
- PostgreSQL과 Redis 사이의 일관성·복구 규칙을 명시해야 한다.
